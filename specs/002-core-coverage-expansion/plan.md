# Implementation Plan: Core Coverage Expansion

**Approved**: User explicitly selected expanding the core and missing topics.
**Feature**: [spec.md](spec.md) | **Boundary**: [coverage.md](coverage.md)

## Technical Context

Keep GNU C++17/GCC, Python3.10+ standard library, existing CLI and unittest
runner, nine exact source pins, compact formatting and per-file permissions.
No new framework/package is planned. Work stays in the current dedicated
worktree; feature001 remains the historical delivery record.

## Constitution Check

Evidence remains content-bound and separate from source/reference status.
Original prose has explicit provenance without inventing an upstream license.
No upstream changes, source-identity hunt, native CPU defaults, missing-core
substitution, fixed page limit, or publication is authorized.

## Shared Contracts

1. Preserve existing integration schema and original examples/helpers/tests.
   New families own disjoint new files and supply complete metadata shards.
2. Add optional `local_references` for original educational Markdown only:
   `path` under `docs/techniques/`, optional `fragment`, nonempty `attribution`,
   `provenance: repository-original`, and `kind: article`. No fictional source
   ID, git pin, public license or tested state is assigned. Reject path escapes,
   wrong file types, and canonical symlink aliases outside the allowed root.
3. Reference-only entries may have pinned references, local educational
   references, or both. Existing entries remain backward compatible. Rendering
   labels local authorship/content identity separately from upstream pins;
   explicit study inclusion is required to copy prose into a notebook.
4. `test --selection-profile PATH` uses the validated ordered profile entries;
   it is mutually exclusive with `--all-core`/`--entry`. Compiler `--profile`
   retains its current meaning. Invalid/empty selections fail before writes.
5. Keep original `core.json`/`compact.json` bytes unchanged. Add
   `expansion.json` (36 additions) and `expanded.json` (original40 + additions).

## Ownership and Execution

The coordinating session owns catalog/profile merges, gap audit and final
acceptance. Four disjoint implementation workers own graph/tree/flow10,
data/DP12, math/games7, and strings/geometry7 files respectively. A separate
tooling worker owns shared CLI/schema/render integration and related Python
tests, using the settled contract above. No worker writes shared catalog,
profiles, evidence or another family's files. Shards are merged only after
handoff, not while still under worker ownership.

Prefer actual compatible upstream implementations; independently authored
algorithmic work is explicitly identified, never disguised as copied upstream
code. Unsupported numeric/input behavior fails explicitly at authored
boundaries or is clearly constrained for unchanged upstream headers.

## Validation Strategy

Each new example and seeded oracle suite compiles independently with baseline
flags and actual include roots. Workers use disjoint build directories and do
not race the shared evidence reports. Final integration reruns all76 with the
content-bound runner and explicitly records results. At least200 small oracle/
exhaustive cases per new entry, plus relevant boundary cases; randomness and
approximation get honest limitations, not probabilistic guarantees.

Existing and added Python tests cover selection, original provenance,
availability, escaping, path confinement, source permissions, staleness and
offline operation. Generate index, unchanged compact/core selections, and new
expansion/expanded notebooks. Compare stable generated bytes and actual browser
search/link behavior. Reproduce in a fresh exported working-tree snapshot,
independently acquiring all nine pins. This is not a committed-HEAD release.
